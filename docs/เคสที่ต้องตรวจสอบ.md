# เคสที่ต้องตรวจสอบ — ความต่างระหว่างระบบเดิมกับระบบใหม่

เอกสารนี้รวบรวมจุดที่ระบบใหม่ **ตั้งใจทำให้เหมือนเดิม** และจุดที่ **ตั้งใจทำให้ต่างจากเดิม**
ไว้ที่เดียว เพื่อให้ตรวจสอบได้ว่าตรงกับที่ตกลงกันไว้

อ่านยังไง

- **กลุ่ม ก** — ผลลัพธ์เหมือนระบบเก่าทุกประการ รวมถึงจุดที่ดูแปลก ถ้าเคยเห็นพฤติกรรมนี้ในระบบเก่า
  จะเห็นเหมือนเดิม **ไม่ต้องทำอะไร** นอกจากยืนยันว่ายังต้องการแบบนี้อยู่
- **กลุ่ม ข** — ตัวเลขหรือพฤติกรรมจะ **ไม่เหมือนเดิม** ต้องรับทราบก่อนใช้งานจริง
- **กลุ่ม ค** — วิธีทำต่างกันแต่ผลลัพธ์ตั้งใจให้เท่ากัน ควรยืนยันด้วยข้อมูลจริงอีกครั้ง

ท้ายแต่ละข้อมีที่อยู่ไฟล์ในโค้ดกำกับไว้ สำหรับคนที่ต้องการตรวจถึงบรรทัด

### ข1. เศษทศนิยมที่เพี้ยนหายไป ⭐ สำคัญที่สุด

**เห็นที่ไหน** ทุกยอดค่าส่วนกลางที่คำนวณใหม่

**เกิดอะไรขึ้น** ระบบเดิมเขียนด้วย JavaScript ซึ่งคำนวณ `50 × 39.8` ได้ `1989.9999999999998`
แล้วบันทึกลงฐานข้อมูลตรง ๆ หน้าจอแสดงทศนิยม 2 ตำแหน่งจึงมองไม่เห็น
แต่พอรวมหลายงวด เศษจะสะสมจนเห็นได้

ระบบใหม่คำนวณได้ `1990.00` พอดี

**ขนาดของความต่าง** ตรวจจากสำเนาข้อมูลจริง 721 งวด พบงวดที่มีเศษติดอยู่ **12 งวด**

ความต่างต่อแถวคือ **0.0000000000002 บาท** (สองในสิบล้านล้านของบาท)
เช่น ฐานข้อมูลเก็บ `2039.9999999999998` ขณะที่ค่าที่ถูกต้องคือ `2040.00`

**ผลกระทบจริง: ไม่มี** หน้าจอและเอกสารทุกใบแสดงทศนิยมสองตำแหน่ง
ต้องรวมยอดประมาณแสนล้านแถวถึงจะขยับได้หนึ่งสตางค์

**ข้อเสนอ: ไม่ต้องแก้ข้อมูลเก่า** การเขียนทับตารางการเงินของจริง
มีความเสี่ยงมากกว่าประโยชน์ที่ได้ ระบบใหม่ไม่สร้างเศษแบบนี้เพิ่มอยู่แล้ว
ถ้าภายหลังอยากได้ข้อมูลที่สะอาดจริง ๆ (เช่น ก่อนเพิ่มข้อบังคับ numeric(x,2))
ค่อยปัดเศษพร้อมกันทีเดียวในช่วงปิดระบบ โดยสำรองข้อมูลก่อน

```sql
-- ปัดเศษให้เหลือสองตำแหน่ง รันเฉพาะในช่วงปิดระบบและสำรองข้อมูลแล้วเท่านั้น
UPDATE gv_payments SET amount_due = ROUND(amount_due, 2)
 WHERE amount_due <> ROUND(amount_due, 2);
```

**หมายเหตุ** เอกสารฉบับก่อนเขียนว่า 37 แถว ซึ่งมาจากการนับบนฐานข้อมูลจริงคนละครั้ง
ตัวเลขที่ยืนยันได้จากสำเนาที่มีอยู่คือ 12 งวด ก่อนตัดสินใจลงมือควรนับใหม่บนฐานข้อมูลจริง
ด้วยเงื่อนไข `amount_due <> ROUND(amount_due, 2)`

### ข12. ฟอร์มลูกบ้านไม่มีช่องเลือกโครงการ

**เห็นที่ไหน** หน้าข้อมูลลูกบ้าน กล่องเพิ่มหรือแก้ไขลูกบ้าน

**เกิดอะไรขึ้น** ระบบเดิมมีช่อง "โครงการ" ให้เลือกและบังคับกรอก
เพราะระบบเดิมไม่มีการตรวจสิทธิ์เลย ใครก็สร้างลูกบ้านให้โครงการไหนก็ได้

ระบบใหม่ผูกลูกบ้านกับโครงการของผู้ใช้ที่ล็อกอินโดยอัตโนมัติ และตัดช่องนี้ออก
เพราะทุกหน้าถูกจำกัดให้เห็นเฉพาะโครงการตัวเองอยู่แล้ว (ดูข้อ ข2)
ส่วนผู้ดูแลระบบที่ต้องดูแลหลายโครงการก็ไม่เห็นเมนูนี้ตั้งแต่แรก

**สิ่งที่ลูกค้าจะสังเกตได้** ย้ายลูกบ้านข้ามโครงการจากหน้าจอไม่ได้อีกแล้ว
ถ้ายังต้องทำ ต้องแจ้งให้เพิ่มเส้นทางเฉพาะขึ้นมา

**หมายเหตุ** ฟอร์มผู้ใช้งานยังมีช่องเลือกโครงการอยู่ เพราะผู้ดูแลระบบ
ต้องสร้างบัญชีให้โครงการอื่นได้จริง

## ข้อที่ยังตรวจไม่ครบ

ต้องบอกตามตรงว่ารายการนี้ยังไม่สมบูรณ์

1. **ยังไม่ได้ไล่หน้าจอของระบบเดิมทีละหน้า** การปัดเศษหรือการจัดรูปแบบตัวเลข
   ที่หน้าจออาจมีอีกชั้นที่ยังไม่พบ
2. **ชื่อผู้สร้างรายการ** ตัดสินใจไม่เหมือนกันระหว่างโครงการ (คงพฤติกรรมเดิมคือไม่บันทึก)
   กับใบเสร็จ (แก้ให้บันทึก) ไม่พบเหตุผลที่บันทึกไว้ว่าทำไมจึงต่างกัน
3. **แท็บรายงาน 2 แท็บที่ยังไม่ได้ทำ** — รายงานค้างชำระแจ้งกรรมการ และแจ้งลูกบ้าน
4. **คอลัมน์รายงานอีก 4 แท็บ** ยังไม่ได้เทียบกับระบบเดิม
